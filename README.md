# GZB運営財務管理 v1.2

バドミントンクラブ等の入出金管理用の静的Webアプリ。外部ライブラリ・API不要。

## GitHub Pagesで公開
1. GitHubで新規リポジトリを作る（例: club-cashflow）。無料プランの場合、通常はPublicリポジトリが必要。
2. ZIPを解凍し、**中のファイルをすべて**リポジトリのルートへアップロード。ZIPそのものではなく、index.html、app.js、manifest.webmanifest、sw.js、アイコン2個、README.mdを置く。
3. Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main / (root) → Save。
4. 発行されたURLをSafariまたはChromeで開く。初回はオンラインで読み込む。
5. iPhone: Safariの共有メニュー → ホーム画面に追加。Android: Chromeメニュー → ホーム画面に追加／アプリをインストール（表示は端末による）。

## 初回設定
設定からクラブ名・通貨（CNY/JPY）・管理開始月・初期繰越金を指定。既存の記録がある場合は通貨変更不可。開始月以降は繰越金が自動計算される。過去の記録修正は以降の残高にも反映される。出金は正の金額で入力し、区分で入金/出金を選ぶ。
設定のサンプル機能は架空の3か月分のデータを投入する。実運用前にサンプルを全削除して初期設定を再確認する。

## レポート
- 月次：繰越、入出金、収支、期末残高、明細。Excelには用途別集計も含む。
- 年間：暦年（1〜12月）の集計、月別一覧、入金・出金の用途別ドーナツグラフ。Excelには年間明細も含む。
- Excelは実際の.xlsx形式（値のスナップショット）。PNGは端末内で生成。月次明細が多い場合は画像を複数枚に分割。保存・共有の可否はブラウザ/OSによる。

## データの保護
- 会計データはブラウザのlocalStorageに保存する。GitHubへのアップロードやクラウド自動同期はしない。GitHub公開URLを知っている他人が、通常、あなたの端末内の記録を見ることはできない。ただしアプリのコードは公開される。端末やブラウザが違えば記録は別々。
- ログイン・権限管理・共同編集・暗号化は未実装。端末を共用する場合は注意する。リポジトリ管理者によるコード変更にも注意。
- 設定 → バックアップ（JSON）を定期的に保存し、安全な場所に保管。復元は全データ置換。Excel・PNGは報告用で、復元用ではない。
- ブラウザのデータ削除、プライベートモード、URL変更等でデータが失われる場合がある。ホーム画面追加時にSafariと別領域になることもあるため、移行時にはJSONを使用する。
- GitHubにはJSONバックアップや実際の会計資料をアップロードしない。

## 更新時
同じURL・同じブラウザで保存データを維持する設計。更新前にJSONをバックアップ。Service Workerのキャッシュ名は更新時に変更する。

## V1.1 追加機能
- 個別登録に加え、一括登録を追加。共通日付を指定し、明細追加で入金・出金を混在させて登録可能。全明細の入力が正しい場合にまとめて保存。
- 出金用途「その他消耗品費用」（体験用ラケット、ガット等）を羽費用の直後に追加。年間集計、Excel、PNGにも反映。
- V1.0と同じ保存キー・データ形式を使用。更新前にJSONバックアップを保存し、同じURLで全ファイルを上書きしてください。V1.1の新用途を含むデータはV1.0に戻すと読み込めないため注意。

## V1.2 追加機能
- 設定 → データのバックアップ・復元に「最終バックアップ日時」を表示。初期表示は「未記録」。JSON出力操作時に更新し、このブラウザに保存する。
- 日時はダウンロード開始操作の記録であり、ファイル保存完了を保証しない。復元操作では更新しない。機種変更時は日時を引き継がない。バックアップ忘れの警告は追加していない。
- 会計データの保存キーとJSON形式はV1.1から変更なし。
